# NetPeek 打包教程

> 面向：需要在开发机上出包、或需要了解安装包内容的开发者。
> 项目分三部分：**采集服务**（`src/NetPeek.Collector`，.NET 8 Windows 服务，ETW 采集，LocalSystem 运行）、
> **桌面 UI**（`src/NetPeek.App`，Tauri 2 + 免构建原生前端）、
> **安装器**（`src/NetPeek.Installer`，WPF 自研单文件安装器，装/卸合一）。
> 安装包 = 一个 `NetPeek.Setup.exe`，内嵌前两者的产物。

## 0. 前置条件

| 工具 | 用途 | 备注 |
| --- | --- | --- |
| .NET 8 SDK | 编译采集服务与安装器 | `dotnet --version` ≥ 8.0 |
| Rust（msvc） | 编译 Tauri 壳 | `rustup` 默认 `stable-x86_64-pc-windows-msvc` |
| Node.js + npm | 跑 Tauri CLI | 前端是免构建的静态 `ui/`，**没有 webpack/vite 这步** |
| WebView2 Runtime | 运行时 | Win11 自带；缺失时安装器会自动下 bootstrapper 静默安装 |

管理员的用处只在**运行**采集服务（ETW 内核会话要权限）和**安装/卸载**（写 HKLM、建服务），
**构建本身不需要**。

## 1. 日常开发调试（不打安装包）

两端分开运行。管理员 PowerShell 默认位于 `C:\Windows\System32`，且 `cd` 到其他工作区经常被拦，
因此管理员一侧直接给出可整行粘贴的完整命令（仓库不在 `D:\NetPeek` 时替换为实际的检出路径）：

```powershell
# 终端 A（管理员）：采集服务，前台控制台模式，连接 ETW 直接采集。整行复制即可，无需 cd
dotnet run --project D:\NetPeek\src\NetPeek.Collector

# 终端 B（普通权限）：桌面 UI，连命名管道 \\.\pipe\NetPeekCollector
cd D:\NetPeek\src\NetPeek.App
npm install   # 首次
npm run dev   # = tauri dev，首次编译 Rust 较慢
```

采集服务未运行时 UI 不会白屏：进程表区会给出「采集服务未连接」空态和「重试连接」按钮（§2.8）。

采集服务也可以用 `pwsh -ExecutionPolicy Bypass -File scripts\dev-collector.ps1` 一条命令启动
（构建 + 清理残留实例 + 提权后台启动 + 确认管道就绪），比手工 `dotnet run` 更可靠。

只改前端（`ui/` 下的 HTML/CSS/JS）时有两个更快的回路：

- `npm run dev` 照常用，改完刷新窗口即生效（无前端编译）；
- 真实应用不便重启时（例如采集服务正被其他会话调试），可用无头预览脚手架：
  `node scripts/preview-v2.mjs [outDir]`——以模拟桥接注入模拟快照，Playwright chromium 按多档视口截图，
  不经过真实管道。需能解析到 `playwright`（未安装在本仓库，用 `NP_PW` 环境变量指向其安装位置）。

安装器的 UI 也有免提权通道：`dist\NetPeek.Setup.exe --preview` 走假流程看界面，
`--shot-all` 直接落三页 PNG 到 `NETPEEK_SHOT_DIR`（缺省 `.workbuddy\tmp`）。

## 2. 出完整安装包（单文件 exe，推荐入口）

一条命令，不用记步骤：

```powershell
pwsh -File D:\NetPeek\scripts\build-installer.ps1
```

产物：`dist\NetPeek.Setup.exe`

脚本做四件事（对应 `build-installer.ps1`）：

1. **`npm run build -- --no-bundle`**：Tauri 编译 release 版 Rust，**不**打 Tauri 自己的
   bundle（`tauri.conf.json` 的 `bundle.targets` 已经是 `[]`，这里再传一次是双保险）。
   产物是主程序 exe，落在 `target/release/`。
2. **`dotnet publish` 采集服务**为 self-contained 单文件（`-r win-x64 --self-contained
   -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true`）——
   服务以 LocalSystem 跑，不能要求用户机器装了 .NET 运行时，所以必须自包含。
   产物先落到 `src/NetPeek.Installer\payload\`。
   这一步前脚本会**先停掉正在运行的采集服务**：运行中的实例独占 exe 映像，
   覆盖它就是 MSB3021「文件被锁定」。这个坑只在采集端**真的改过**时才暴露
   （没改动时 MSBuild 判定输出最新、跳过拷贝，看起来一切正常），所以别手动跳过这步。
3. **填充 payload**：`payload\NetPeek.exe`（主程序）+ `payload\NetPeek.Collector.exe`，
   csproj 按名把它们作为 `EmbeddedResource` 内嵌（`LogicalName` 固定）。
4. **`dotnet publish` 安装器**为单文件 self-contained 压缩 exe，版本号从
   `tauri.conf.json` 读取与主应用对齐，产物即 `dist\NetPeek.Setup.exe`。

内嵌产物（约 52MB）不入 git，`.gitignore` 排除了 `payload/`。csproj 里两个 `EmbeddedResource`
都带 `Exists` 条件，所以开发机上没有 payload 也能正常编译（`--preview` 跑 UI 没问题，
真安装会在解包一步报「内嵌产物缺失」并提示回到本脚本重建）。

首次构建要全量编译 Rust，慢是正常的；之后增量。

## 3. 安装包包含的组件

| 组件 | 去向 | 谁负责 |
| --- | --- | --- |
| NetPeek UI（单 exe + 内嵌前端） | `INSTALLDIR\NetPeek.exe` | `InstallFlow.WriteFiles` |
| `collector\NetPeek.Collector.exe` | `INSTALLDIR\collector` | 同上 |
| 安装器自身副本（卸载器） | `INSTALLDIR\NetPeek.Setup.exe` | 同上 |
| Windows 服务注册 | 服务名 `NetPeek.Collector` | `InstallFlow.SetupService` |
| WebView2 检测/引导 | 系统级 | `InstallFlow.EnsureWebView2` |
| 快捷方式 | 开始菜单组 + 可选桌面 | `InstallFlow.CreateShortcuts` |
| 卸载登记 | `HKLM\...\Uninstall\NetPeek` | `InstallFlow.WriteUninstallKey` |

服务的关键行为写在 `src/NetPeek.Installer/Install/Svc.cs`，改服务安装逻辑改那里：

- `obj= LocalSystem`、`start= auto`：ETW 需要内核权限，开机自启；
- `binPath` 写进注册表时**带引号**：否则 Program Files 的空格会触发经典 unquoted
  service path 提权（SCM 会去找 `C:\Program.exe`）；
- `sc failure actions= restart/60000`×3：采集端崩溃 60 秒后自动拉起，不等人手动重启；
- 升级与卸载都是先 `net stop` + `sc delete`、等真正 STOPPED，再重建同名服务
  （不等就会撞 1072 ERROR_SERVICE_MARKED_FOR_DELETE）。

装完可以验证：

```powershell
sc.exe query NetPeek.Collector        # 服务在跑
sc.exe qc NetPeek.Collector           # binPath 指向安装目录 collector\ 下且带引号
```

用户侧数据（设置、主题、历史库）位于 `%APPDATA%\com.netpeek.app`，
WebView2 缓存位于 `%LOCALAPPDATA%\com.netpeek.app\`。

## 4. 只出 UI 的绿色包（不装服务）

调试或内测时可以只编主程序 exe 不打安装器：

```powershell
cd src\NetPeek.App
npm run build          # --no-bundle 已由 tauri.conf.json 的 targets:[] 保证
```

注意这个 exe 只是壳，没有采集服务就没有数据——适合验证主题/布局/历史回放，不适合验收采集链路。

## 5. 版本号与升级

几个地方写着 `0.1.0`，语义不同：

| 文件 | 作用 | 发新包时的处理 |
| --- | --- | --- |
| `src/NetPeek.App/src-tauri/tauri.conf.json` → `version` | **安装器版本号**（脚本读取后传给 `-p:Version`） | 必须修改 |
| `src/NetPeek.App/src-tauri/Cargo.toml` → `version` | Rust crate 版本 | 同步修改，保持一致 |
| `src/NetPeek.App/package.json` → `version` | npm 包元数据 | 同步修改 |
| `src/NetPeek.Collector/NetPeek.Collector.csproj` | 采集服务程序集版本 | 可选，建议同步 |
| `src/NetPeek.Installer/NetPeek.Installer.csproj` → `Version` | 安装器程序集版本 | **不用手改**，被脚本的 `-p:Version` 覆盖 |

安装器版本号只影响控制面板「应用」里显示的版本与升级键，同版本重复安装走的是覆盖安装路径
（`RemoveLegacy` 清理旧服务与旧文件）。有改动就提升版本号，别依赖同版本覆盖。

## 6. 常见问题

- **重编报 `MSB3021`/`MSB3027 文件被 NetPeek.Collector 锁定**：`build-installer.ps1` 会先停
  采集服务；手工跑 `dotnet publish` 时得自己先 `pwsh -File scripts\dev-collector.ps1 -Stop`，
  或者用 `-o` 指一个临时目录绕开锁。UI 侧同理：关窗是「隐藏到托盘」，进程不退出，
  先 `taskkill /IM NetPeek.exe /F`（采集服务 exe 不需要处理）。
- **`图标换过了但任务栏还是旧的`**：图标嵌在 exe 资源里，重新构建才生效；图标源文件在
  `src-tauri/icons/`，修改后要同步五个产物（`icon.ico` 的多尺寸档 + `icon-32/128.png` 等）。
- **杀毒软件误报单文件 exe**：self-contained 单文件是误报高发对象；被拦时将安装包与
  `NetPeek.Collector.exe` 加入白名单即可。
- **安装报「WebView2 引导器数字签名校验失败」**：下载被中间人替换或证书被吊销，安装器会拒绝
  执行（这是有意的）。从 https://developer.microsoft.com/microsoft-edge/webview2 手动装
  Evergreen Runtime 后重试。
- **安装报「旧采集服务未能在 10 秒内停止」**：服务卡在「停止中」，重启系统后重跑安装程序。
- **安装报「创建采集服务失败 / 1072」**：同样是旧服务尚未完全停止，重启后重试。
- **服务装上了但 UI 显示「异常（ETW 会话需要管理员权限）」**：看服务是否真的以 LocalSystem
  在跑（`sc.exe qc`），以及是否被组策略拦了内核事件访问。

## 7. 打包后的验证

仓库自带一组验证脚本（均需管理员权限，同样从 System32 起步时使用全路径）：

```powershell
pwsh -File D:\NetPeek\scripts\verify-collection.ps1        # 管道出数、按进程归因
pwsh -File D:\NetPeek\scripts\verify-pause.ps1             # 暂停/恢复
pwsh -File D:\NetPeek\scripts\verify-etw-scenarios.ps1     # Event 18 去重、重传分离等场景
```

安装包的最小验收路径：双击 `dist\NetPeek.Setup.exe`（一次 UAC）→ 服务自动启动 →
打开 UI 见实时流量 → 「设置 - 应用」里点卸载（或跑 `NetPeek.Setup.exe --uninstall --silent`）→
`sc.exe query NetPeek.Collector` 报 1060（服务不存在）→ `%APPDATA%\com.netpeek.app` **已被删除**。

安装/卸载的完整日志在 `%ProgramData%\NetPeek\setup.log`，这是用户报障时唯一的证据面
（卸载成功时清掉，失败则保留）。失败后安装器还会做补偿清理：停删服务、删快捷方式与卸载键，
程序文件保留以便直接覆盖重装。
