# NetPeek 打包教程

> 面向：需要在开发机上出包、或需要了解安装包内容的开发者。
> 项目分两部分：**采集服务**（`src/NetPeek.Collector`，.NET 8 Windows 服务，ETW 采集，LocalSystem 运行）
> 和 **桌面 UI**（`src/NetPeek.App`，Tauri 2 + 免构建原生前端）。安装包 = MSI，一个包装两样东西。

## 0. 前置条件

| 工具 | 用途 | 备注 |
| --- | --- | --- |
| .NET 8 SDK | 编译采集服务 | `dotnet --version` ≥ 8.0 |
| Rust（msvc） | 编译 Tauri 壳 | `rustup` 默认 `stable-x86_64-pc-windows-msvc` |
| Node.js + npm | 跑 Tauri CLI | 前端是免构建的静态 `ui/`，**没有 webpack/vite 这步** |
| WebView2 Runtime | 运行时 | Win11 自带；安装包缺它时 Tauri 会自动下 bootstrapper |
| WiX Toolset | 打 MSI | 不用手动装，Tauri 首次打 MSI 时自动下载 |

管理员的用处只在**运行**采集服务（ETW 内核会话要权限），**构建本身不需要**。

## 1. 日常开发调试（不打安装包）

两端分开运行。管理员 PowerShell 默认位于 `C:\Windows\System32`，且 `cd` 到其他工作区经常被拦，
因此管理员一侧直接给出可整行粘贴的完整命令（仓库不在 `D:\code\NetPeek` 时替换为实际的检出路径）：

```powershell
# 终端 A（管理员）：采集服务，前台控制台模式，连接 ETW 直接采集。整行复制即可，无需 cd
dotnet run --project D:\code\NetPeek\src\NetPeek.Collector

# 终端 B（普通权限）：桌面 UI，连命名管道 \\.\pipe\NetPeekCollector
cd D:\code\NetPeek\src\NetPeek.App
npm install   # 首次
npm run dev   # = tauri dev，首次编译 Rust 较慢
```

采集服务未运行时 UI 不会白屏：进程表区会给出「采集服务未连接」空态和「重试连接」按钮（§2.8）。

采集服务也可以用 `pwsh -ExecutionPolicy Bypass -File scripts\dev-collector.ps1` 一条命令启动
（构建 + 清理残留实例 + 提权后台启动 + 确认管道就绪），比手工 `dotnet run` 更可靠。

只改前端（`ui/` 下的 HTML/CSS/JS）时有两个更快的回路：

- `npm run dev` 照常用，改完刷新窗口即生效（无前端编译）；
- 真实应用不便重启时（例如采集服务正被其他会话调试），可用无头预览脚手架：
  `node scripts/preview-v2.mjs [outDir]`——以模拟桥接注入模拟快照，Playwright chromium 按多档视口截图，
  不经过真实管道。需能解析到 `playwright`（未安装在本仓库，用 `NP_PW` 环境变量指向其安装位置）。

## 2. 出完整安装包（MSI，推荐入口）

一条命令，不用记步骤：

```powershell
pwsh -File D:\code\NetPeek\scripts\build-installer.ps1
```

产物：`src/NetPeek.App/src-tauri/target/release/bundle/msi/*.msi`

脚本做三件事（对应 `build-installer.ps1`）：

1. **发布采集服务**为 self-contained 单文件（`dotnet publish -r win-x64 --self-contained`）——
   服务以 LocalSystem 跑，不能要求用户机器装了 .NET 运行时，所以必须自包含；
   单文件产物先落到 `src-tauri/installer/collector/`，再复制一份到 `target/release/`
   （WiX light 的工作目录，`collector.wxs` 的 `File Source` 相对路径从那里解析）。
2. **`npm run build -- --bundles msi`**：Tauri 编译 release 版 Rust 并打 MSI；
   WiX fragment `src-tauri/installer/collector.wxs` 会在这个阶段被合并进来。
3. 校验产物存在并打印路径和体积。

首次构建会下载 WiX 工具链并全量编译 Rust，慢是正常的；之后增量。

## 3. 安装包包含的组件

| 组件 | 去向 | 谁负责 |
| --- | --- | --- |
| NetPeek UI（exe + 资源） | `INSTALLDIR` | Tauri MSI 主体 |
| WebView2 检测/引导 | 系统级 | Tauri bundler |
| `collector\NetPeek.Collector.exe` | `INSTALLDIR\collector` | `collector.wxs` fragment |
| Windows 服务注册 | 服务名 `NetPeek.Collector` | 同上 `ServiceInstall` |

服务的关键行为都写在 `collector.wxs` 里，改服务安装逻辑改那里：

- `Account="LocalSystem"`、`Start="auto"`：ETW 需要内核权限，开机自启；
- `ServiceControl Start="install" Stop="both" Remove="uninstall"`：**装完即启动，卸载时先停后删**；
- 升级走 Tauri 生成的 MajorUpgrade，旧版本先卸干净再装新版本。

装完可以验证：

```powershell
sc.exe query NetPeek.Collector        # 服务在跑
sc.exe qc NetPeek.Collector           # binPath 指向安装目录 collector\ 下
```

用户侧数据（设置、主题、历史库）位于 `%APPDATA%\com.netpeek.app`，卸载时不会清除。

## 4. 只出 UI 的绿色包（不装服务）

调试或内测时可以只编 exe 不打安装器：

```powershell
cd src\NetPeek.App
npm run build          # 产物在 src-tauri\target\release\netpeek-app.exe 附近
```

注意这个 exe 只是壳，没有采集服务就没有数据——适合验证主题/布局/历史回放，不适合验收采集链路。

## 5. 版本号与升级

四个地方写着 `0.1.0`，语义不同：

| 文件 | 作用 | 发新包时的处理 |
| --- | --- | --- |
| `src/NetPeek.App/src-tauri/tauri.conf.json` → `version` | **MSI 产品版本**、MajorUpgrade 判断 | 必须修改 |
| `src/NetPeek.App/src-tauri/Cargo.toml` → `version` | Rust crate 版本 | 同步修改，保持一致 |
| `src/NetPeek.App/package.json` → `version` | npm 包元数据 | 同步修改 |
| `src/NetPeek.Collector/NetPeek.Collector.csproj` | 采集服务程序集版本 | 可选，建议同步 |

同版本号重复安装走的是修复/覆盖路径，行为随 Tauri 版本有差异——有改动就提升版本号，不要依赖同版本覆盖。

## 6. 常见问题

- **重编报 `failed to remove netpeek-app.exe: 拒绝访问 (os error 5)`**：上一个 dev 实例仍在运行——
  该应用关窗为「隐藏到托盘」，进程不退出，exe 被其占用。先 `taskkill /IM netpeek-app.exe /F`
  再重新运行（服务 `NetPeek.Collector.exe` 无需处理）。
- **MSI 里装了旧版采集服务**：`build-installer.ps1` 每次都会重新 `dotnet publish` 并覆盖，
  但如果绕过脚本手动 `npm run build`，WiX 用的是 `target/release/` 里上一次复制的
  `NetPeek.Collector.exe`。修改采集服务代码后，**务必从脚本入口打包**。
- **`图标换过了但任务栏还是旧的`**：图标嵌在 exe 资源里，重新构建才生效；图标源文件在
  `src-tauri/icons/app-icon.svg`（完整版）与 `icon-small.svg`（≤32px 简化档），修改后重出
  `icon.ico` 的 7 个尺寸档。
- **杀毒软件误报单文件 exe**：self-contained 单文件是误报高发对象，MSI 安装路径的服务一般无碍；
  被拦时将采集服务 exe 加入白名单即可。
- **首次 MSI 构建失败说找不到 light.exe**：WiX 还没下完，重跑一次脚本；公司网络拦截下载时
  配置 `WIX` 环境变量指向本地 WiX。
- **服务装上了但 UI 显示「异常（ETW 会话需要管理员权限）」**：看服务是否真的以 LocalSystem
  在跑（`sc.exe qc`），以及是否被组策略拦了内核事件访问。

## 7. 打包后的验证

仓库自带一组验证脚本（均需管理员权限，同样从 System32 起步时使用全路径）：

```powershell
pwsh -File D:\code\NetPeek\scripts\verify-collection.ps1        # 管道出数、按进程归因
pwsh -File D:\code\NetPeek\scripts\verify-pause.ps1             # 暂停/恢复
pwsh -File D:\code\NetPeek\scripts\verify-etw-scenarios.ps1     # Event 18 去重、重传分离等场景
```

安装包的最小验收路径：MSI 静默装（`msiexec /i xxx.msi /qn`）→ 服务自动启动 → 打开 UI 见实时流量 →
卸载后 `sc.exe query NetPeek.Collector` 报 1060（服务不存在）→ `%APPDATA%\com.netpeek.app` 仍在。
