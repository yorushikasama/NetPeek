# NetPeek 功能清单

## 启动（窗口居中 + 启动动效 + 单实例）（2026-09-14 新增）

- **启动时窗口落在显示器工作区正中**：配置 `"center": true`，按 work_area（已扣掉任务栏）
  计算，多屏时落在主屏。此前没指定位置，落到 Windows 的 `CW_USEDEFAULT` 默认落点上，
  实测偏右下（四边留白 左 82 / 右 68 / 上 75 / 下 45）
- 冷启动揭示：窗口在**首绘完成时**才出现（配置 `visible:false`，由前端 `boot.js` 调 `show()`），
  出现即播放 2.4 秒品牌动效（2000ms 动效 + 400ms 定格）——
  版式上浮淡入、主波自左向右描线、外发光滞后 140ms 跟随并过曝呼吸一次、
  次级暗波滞后 420ms 跟上、字标 "NetPeek" 自左向右擦除揭示、末尾定格
- 版式：**只有源图标里的两条波形线 + 字标**，不含圆角底片（启动页本身就是整窗底色，
  再套一层底片会变成「窗口里放了个窗口」）；标记占窗口宽约 1/3，整块严格居中
- 揭幕时机：界面就绪 **且** 动效至少播完一遍，取两者较晚者；
  两级回退保护（界面迟迟不就绪 → 播完再等 1.6s 卸层；硬上限 6s 无条件卸层），
  任何情况下都不会把用户关在启动页
- 配色跟随皮肤：深色皮肤用品牌琥珀（源图本色），**浅色皮肤自动换一套压过明度的琥珀**
  （深底那套的峰顶在浅底对比度只有 1.25:1，整条波形几乎不可见）；
  另提供中性反白预设（完全符合 tokens.css「琥珀不进 chrome」的约束）
- 尊重 `prefers-reduced-motion`：不播动画、直接呈现完成态
- 只在页面加载时出现一次；隐藏到托盘再唤出不重播（高频操作，每次重播会变成噪音）
- **单实例守卫**：重复启动不会开出第二个窗口，而是把已有窗口唤到前台
  （隐藏/最小化都收拢，与托盘「打开主界面」同一条路径）。
  此前没有守卫，实测一度同时存活 3 个 `netpeek-app.exe` ——
  三份托盘图标、三份采集管道连接、三份历史库连接

## 屏 0：外观与主题（2026-09-02 新增，2026-09-03 调整为三模式）

> **2026-09-12 起「三模式」已退役，本节按皮肤模型重读。** 实现里没有「模式」这个维度了 ——
> 外观并入设置屏（不再是独立的屏 0），取而代之的是**皮肤**：一套预设包 = 一整份设计令牌。
> 对照关系：
> - 出厂皮肤 `plain` / `light` / `amber`（`theme.js` 的 `SKINS`）承接原「模式 3 定制化主题」的预设部分；
> - 皮肤 `image`（跟随背景图）承接原「模式 1 标准离线取色」，**AI 取色降级成它下面的一个高级选项**
>   而不再是并列的「模式 2」——它产出的仍然是同一份令牌表，失败回落离线取色；
> - 「自定义皮肤」承接原模式 3 的手工调令牌部分，可命名另存、随时切回。
>
> 下面这份原文保留为设计意图记录（哪些能力必须有），读它时把「模式 N」按上面的对照换成皮肤。

三个并列模式，输出同一组设计令牌，主题可保存复用：

- **模式 1：自定义背景 + 标准离线取色**（默认）：背景来源为默认深色 / 内置壁纸若干 / 自定义本地图片；从图片提取主色，自动生成强调色、玻璃面板底色、文字明暗；提供微调（面板不透明度、背景模糊强度两个滑杆）；完全离线、即时生效
- **模式 2：自定义背景 + AI 自适应（可保存）**：把图片缩略图发送给多模态模型，返回整套配色与焦点区域；首次使用需授权（明示”缩略图将上传至所选服务”），提供方可选；结果按图片缓存，**可命名保存到主题列表**直接复用；生成失败或断网自动回退标准模式
- **模式 3：定制化主题**：内置预设主题若干（经典深色 / 经典浅色 / 高对比等），一键启用；可手动定制各设计令牌与微调参数，保存为自定义主题
- 主题列表：保存、切换、重命名、删除；当前激活主题持久化
- 焦点避让：自动检测画面主体位置，面板默认避开焦点区域；用户仍可手动拖动窗口
  —— **未实现**（截至 2026-09-15）。显著性检测尚未实现，面板位置为固定布局。
  README 的「已知限制」中同样记录了这一条，两处需保持一致
- 实时预览：换图、换模式、调滑杆即时预览，可一键还原默认
- 跟随系统深浅色（2026-09-12 恢复）：开关开启后，朴素 / 浅色皮肤随系统深浅自动切换；琥珀、跟随背景图、自定义皮肤不受影响；主界面与迷你窗同步
- 全局界面不透明度（2026-09-12 新增）：50%–100% 滑杆，主界面、迷你窗与能量球整体半透，桌面壁纸透出；拖动即时预览，50% 为可读下限

## 屏 1：主界面「实时」

- 顶栏：应用图标与名称；监控状态（监控中 / 已暂停 / 服务异常）；总下载速率、总上传速率、今日合计流量；搜索框输入即筛；深浅色切换；设置入口
- 右栏「今日」卡上的「详情」（2026-09-16 补）：实时屏里唯一指向「更早的数据」的入口，
  点击后跳到历史屏并**自动选中今天**（此前只切屏、停在「近 30 天 + 未选中」，需用户再次手动查找）
- 实时速率总览：总上传 / 总下载速率随时间变化图，时间窗切换 10s / 1m / 5m，悬浮显示某一时刻的速率数值
- 应用榜单：横向 Top 4 应用卡片，每张显示应用图标、名称、实时下载 / 上传速率、占总量百分比
- 进程列表主表格，列：应用图标 | 应用名 | 对端 | PID | 下载速率 | 上传速率 | 近 24 小时
  - 「近 24 小时」＝该进程实例（应用视图下为该应用）最近 24 小时的下载 + 上传合计，
    取自历史库 `minute_stats`；库里查不到记录时显示 `—`，不写 `0 B`；
    悬浮看下载 / 上传明细；整分钟翻转后自动刷新
  - 点击列头排序，**三态循环**：该列首选方向（文本列升序、其余降序）→ 反向 → 取消排序。
    取消后回到默认呈现（**合计从高到低**，＝下载 + 上传）且表头不标箭头；表格卡片头另有
    「恢复默认排序」按钮，排序生效时露出，一步复位（2026-09-14 补：此前只有两态，点完
    列头没有地方可以取消；2026-09-16 补：默认键从「下载」改成「合计」——「占带宽」是
    双向的，做种 / 推流 / 网盘同步这类上传较重的应用不再被挤出可视区域。合计没有对应列头，
    因此点击任意一列的第一下都会真正触发重排）
  - 整行占比条（2026-09-16）：行背景一条从左起的极淡色。长度 = 这一秒合计流量占**最高那
    一行**的比例；颜色 = 该行的主方向（下载为主用下载色、上传为主用上传色）—— 条的长度
    表示流量多少、条的颜色表示主要方向，因此「条满格 + 上传色」即表示该机器正在大量上传
  - 搜索过滤（与顶栏搜索联动；统一前缀语义：`=x` 精确、`!=x` 不等于、`!x` 不含、
    默认包含；维度覆盖应用名 / 完整路径 / PID / 对端 IP / 端口 / 服务名 / 国家码 / 保留地址标签）
  - 视图切换：按应用聚合 / 按进程明细（聚合行取流量最大成员的对端）
  - 选中一行后右侧弹出详情窗格
  - 值可复制（2026-09-14）：对端 IP / 应用名 / 路径 / 累计量 / 数值都可拖选后 `Ctrl+C`；
    在任意位置右键弹出**应用自己的菜单**（不是 WebView2 原生菜单），按上下文给
    「复制对端地址 / 复制应用名 / 复制 PID / 复制下载 / 复制上传 / 复制近 24 小时」
    与「复制整行（制表符分隔，可直接粘进表格）」；有选中文本时首项是「复制选中内容」。
    输入框（搜索、API Key、日期）保留系统菜单 —— 剪切 / 粘贴 / 全选要靠它
- 右侧详情窗格（选中应用后显示）：
  - 应用图标、名称、完整路径、PID、会话时长、本秒最热对端（国旗或保留地址语义图标 + IP:端口 + 服务名）
  - 该应用近 1 小时速率曲线
  - 该应用近 30 天每日用量柱状图
  - 「归因说明」入口，解释代理 / VPN / WSL 场景下流量的归因边界
- 底部状态栏：
  - ETW 丢事件提示（无丢失时显示「监控正常」）
  - 服务运行状态
  - 本次会话已采集时长
  - 归因覆盖率（如 96% 归因到应用 / 4% 系统未归因）

## 屏 2：迷你窗（托盘小窗）（2026-09-03 新增；2026-09-05 按 §2.9 改版；2026-09-12 修边框与球体材质）

- 同一窗口两种形态：**能量球**（球体 92×92，窗口 108×108；双层环形规 + 中心总速率）
  ⇄ **迷你窗**（面板 320×300，**窗口 344×324**，四周各 12px 留给外发光与投影）
- 能量球点击展开为迷你窗；迷你窗「—」收回能量球；「×」隐藏小窗
- 能量球带球面光照（球面明暗 + 受光方向的镜面高光 + 底部环境反光），
  并随流量点亮球缘光环、球心光斑、旋转高光叶与 canvas 轨道粒子；
  暂停时定格、断连只留暗淡轮廓
- 窗口置顶、透明（`decorations: false` + **`shadow: false`**）、可拖动
  （拖动由前端 5px 位移阈值触发系统 `startDragging`）
- 迷你窗：头部状态圆点 + 总下载 / 总上传实时速率；中部 Top 5 应用（真实图标、名称、
  速率，按当前速率排序，整行琥珀渐变表示占比）；底部「暂停 / 主界面」两按钮
- 「退出」在托盘右键菜单，不在小窗里
- 由托盘菜单「打开迷你窗」显示 / 隐藏

## 屏 3：历史统计

- 日期范围选择（已完成，2026-09-11）：近 7 天 / 近 30 天 / 近 90 天 / 自定义（任意起止日期，后端 `history_range` 命令，见开发进度 §11）
- 自定义区间（2026-09-16 重做，见开发进度 §50）：
  - **起止各带一个时刻**（`全天 / 00:00 … 23:00` 下拉，默认全天）。区间 ≤ 72 小时时柱图
    自动切成**小时柱**；更长则按天聚合，**时刻字段整体收起**（避免灰显控件被误解为故障，
    实际是「该档位无需时刻」—— 该说明由底部回执给出）。收起**不清空**：将日期改回后，
    上次选择的整点仍然保留
  - **粒度是回执、不是表单状态**：底部一行 `按小时聚合 · 共 18 小时` /
    `按天聚合 · 共 11 天（超过 3 天，时刻不参与）` / 更长时改为「按周聚合」。回执和柱图
    读的是同一套骨架（`planQuery`），因此「共 N 小时」与点击后实际渲染的柱数始终一致
  - 默认值落在**今天**（而非整个可见区间）：打开即为小时档，不会先呈现一组当前档位无需的控件
  - 日期框与时刻框都走**应用自绘的浮层**（`date-picker.js` / `select-menu.js`）：
    Chromium 原生 `input[type=date|time]` 的弹层是独立 PagePopup，页面 CSS 无法作用于它
    （只有 `color-scheme` 能切换深浅，强调色永远是内置蓝），与皮肤必然无法对齐
- 每日总量柱状图（上传 / 下载分开统计）；长区间按**自然周**归组（周一起），首尾半周按实际天数计
- 明细表：应用 | 下载合计 | 上传合计 | 占比 | 趋势箭头；排行按合计降序（`TOP_N` 截断）
- 从实时屏「今日合计」卡点「详情」进来时**自动定位到今天**（`setScreen('history', { focusToday: true })`）；
  当前自定义区间不含今天时先回到 30 天默认档，而不是擅自修改用户选择的区间
- 导出 CSV：**跟随屏幕上当前看到的范围**（选中某一天就只导那一天，见开发进度 §50）
