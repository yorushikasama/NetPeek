# NetPeek 执行计划

配套文档：[技术选型.md](技术选型.md)

单人全职：MVP 约 5–6 周，含历史数据、安装包和兼容测试的首个公测版约 8–10 周。2026-09-02 起 UI 栈调整为 Tauri 2 并新增自适应主题引擎阶段（3.5），整体增加约 1 周。

## 架构

```text
NetPeek.App                        NetPeek.Collector
普通权限 Tauri 2 托盘程序           LocalSystem Windows Service
        │                                   │
        │  Named Pipe，每秒一次快照          │  ETW 网络事件
        ├───────────────────────────────────┤
        │                                   │
进程列表、实时速率、图表              payload PID + 方向 + 字节聚合
历史查询、设置                       进程元数据、接口计数、丢事件检测
                                            │
                                            ▼
                                       SQLite 分钟汇总
```

安装时提权一次装服务，之后 UI 以普通用户权限运行，不需要每次弹 UAC。

## 构建顺序（2026-09-02 决策）

1. **底层优先**：先做 C# 采集服务（ETW 会话 + 聚合 + Named Pipe），这是数据正确性的根基，UI 先占位可运行即可。
2. **UI 精修延后**：主窗按 B（沉浸式全屏）、迷你窗按 C 的版式，在采集服务稳定后再精修。
3. **工程框架先行**：先搭出可编译的解决方案骨架与 IPC 协议，再逐段填充 ETW 解析。

### 解决方案结构

```text
NetPeek.sln
├─ src/NetPeek.Shared/       # IPC 协议 DTO（服务与 UI 共用契约）
├─ src/NetPeek.Collector/    # .NET 8 Windows Service（ETW + 聚合 + Named Pipe 服务端）
└─ src/NetPeek.App/          # Tauri 2（前端 + Rust 外壳），占位阶段
```

### 环境前提（2026-09-02 实测）

- .NET 8 SDK 8.0.422：已装，后端可立即编译。
- Node 24 / npm 11：已装。
- **Rust / cargo：未装**，Tauri 2 需要先安装 Rust 工具链（`winget install Rustlang.Rustup` 或 rustup-init）才能 `tauri dev`/`tauri build`。

## 阶段

### 阶段 1：ETW 验证（3–5 天）

已部分完成：本机实测确认 TCP/UDP 收发事件带 PID 和字节数，且必须用 payload PID。详见技术选型文档第 1 节。

剩余待验证：浏览器下载、`curl`、短连接、IPv6、QUIC、进程快速退出、休眠恢复、以及与其他性能分析工具同时开 ETW 会话时的行为。覆盖 Windows 10 22H2 和 Windows 11。

本阶段只写控制台程序，不碰 UI。

出口条件：归因准确率可接受，且确认丢事件可控。不满足就要重新评估 WFP 路线。

### 阶段 2：采集服务（5–7 天）

Windows Service 骨架、ETW 会话生命周期管理、分片计数器、PID 复用处理、进程元数据缓存、Named Pipe 服务端、每秒快照。

记录 `EventsLost`。服务异常退出后要能清理或复用残留的 ETW 会话，否则重启后开不起来。

### 阶段 3：桌面 UI（8–10 天）

先立设计系统再写界面：字号阶梯、4 px 栅格、上传/下载配色、设计令牌结构、图标族统一。规范见技术选型文档 4.1 节。

UI 技术栈为 **Tauri 2**（2026-09-02 起，原因见技术选型 4.3）：前端 React/Svelte 任选其一，样式全部走 CSS 变量；托盘用 Tauri 原生 tray API；图表用 canvas 库（uPlot 优先，ECharts 按需）。性能纪律：速率与表格更新走局部状态，禁止整树重渲染，每秒固定一次刷新，隐藏窗口时停止图表重绘。

功能：托盘、虚拟化进程表格、实时速率、累计流量、排序与搜索、Top N 折线图。

美观性验收：深浅色各一套截图；100% / 150% / 200% 缩放下无模糊错位；窗口最小宽度下布局不破；数字刷新时列宽不跳动；空态、服务未启动、ETW 丢事件都有明确文案；正文对比度 ≥ 4.5:1，可键盘遍历。

### 阶段 3.5：自适应主题引擎（5–7 天）

标准自适应先行（它是默认项也是 AI 的兜底）：图片缩略、色板提取、令牌推导、对比度校验器、显著性焦点避让、实时预览。之后接 AI 自适应：提供方接口、授权流程、按图片哈希缓存、校验不过自动回退标准模式。两模式输出同一组 CSS 变量，UI 不感知来源。

验收：任意测试图下文字对比度全部 ≥ 4.5:1；AI 模式断网/超时/返回非法 JSON 时 200 ms 内回退标准模式；同一图片二次加载不重复请求。

### 阶段 4：历史与设置（4–6 天）

SQLite 分钟聚合、批量事务写入、保留策略（默认 30 天分钟数据后压缩）、开机启动、单位与保留期设置。

### 阶段 5：稳定性与发布（5–7 天）

跑完技术选型文档第 12 节的全部验收场景。出 WiX MSI，验证安装、卸载、服务权限、升级和残留清理。

## 功能范围

### P0 首版必须有

按应用和进程的实时上传/下载速率；本次会话累计流量；TCP/UDP/IPv4/IPv6；托盘运行、暂停监控、退出；程序名称/路径/图标/PID；搜索、排序、Top 流量应用；系统与未归因流量单独显示；ETW 丢事件与采集异常状态提示；服务随系统启动，UI 可选登录启动；跟随系统的深浅色主题；**自定义背景图；标准自适应主题（离线）；AI 自适应主题（含授权、缓存与回退）**。

### P1 后续

分钟历史与日/月汇总；按网卡和网络类型分类；流量限额与超额通知；`svchost.exe` 服务映射；UWP/MSIX 应用聚合；浏览器多进程聚合；CSV 导出；睡眠与网络切换处理。

### 首版明确不做

防火墙、限速、断网、域名分析、逐连接抓包。这些会大幅扩大权限、安全和网络栈兼容范围。

## 主要风险

| 风险 | 应对 |
| --- | --- |
| 用错事件头 PID 导致归因错误 | 已实测确认，统一读 payload PID |
| 累加 Event ID 18 导致下载量翻倍 | 明确忽略该事件 |
| 高包速率丢事件 | 加大缓冲区，回调内只做累加，监控 `EventsLost` |
| .NET 服务内存超预算 | 仅替换采集服务为 C++20，UI 不动 |
| 代理/VPN 场景归因不符合用户预期 | 界面与文档明说归因边界，不摊派差额 |
| 未签名安装包被 SmartScreen 拦 | 发布前准备代码签名证书 |
| 主题库维护中断或与 .NET 版本不兼容 | 已改用 Tauri 2 + CSS 变量，主题依赖自研令牌系统，无第三方主题库 |
| 高频刷新导致界面卡顿或图表掉帧 | 固定 1 秒刷新节奏，局部状态更新禁止整树重渲染，表格虚拟化，隐藏窗口停止重绘，图表用 canvas 库只画 Top N |
| WebView2 缺失或过旧（Tauri 依赖） | 安装包做运行时检测与引导安装，首启前校验 |
| AI 自适应泄露用户壁纸、产生费用或失效 | 首次使用明示授权、提供方可选、缩略图 ≤512px、按哈希缓存、校验不过回退标准模式、保留“仅标准模式”开关 |
