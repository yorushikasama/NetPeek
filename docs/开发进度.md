## 2. 已完成并验证的功能

### 采集端（`src/NetPeek.Collector`）

- **ETW 会话**（`Sources/EtwSnapshotSource.cs`）：会话名 `NetPeek.Collector`，订阅 `KernelTraceEventParser.Keywords.NetworkTCPIP`，覆盖 TCP/UDP 的 IPv4+IPv6 收发与重传。启动时清理残留同名会话。
- **归因规则**：统一读 payload PID（TraceEvent 已在 `FixupData` 把 payload PID 写回 `data.ProcessID`）；**刻意不订阅 Event ID 18**（`TcpIpTCPCopy`），否则下载量翻倍；重传单独累计，不混入上传量。
- **PID 复用处理**：进程身份键 = PID + 进程启动时间，检测到复用则清零重计。进程退出且连续 30 帧无流量后从字典移除。
- **命名管道服务端**（`Ipc/SnapshotPipeServer.cs`）：`\\.\pipe\NetPeekCollector`，`PipeDirection.Out` 单向，帧格式 = 4 字节小端长度 + UTF-8 JSON，1000ms 一帧。客户端断开后自动回到监听。
- **反向控制通道**（`Ipc/SnapshotControlServer.cs`，新增）：`\\.\pipe\NetPeekCollectorControl`，`PipeDirection.In`。命令为单行 UTF-8 文本 `pause` / `resume` / `toggle`（不区分大小写）。UI 每发一条命令建一次短连接，写完即断。
- **暂停语义**：`ISnapshotSource` 增加 `Pause()` / `Resume()` / `IsPaused`。暂停时 ETW 回调内 `Add`/`AddRetransmit` 直接短路（不再累计），`GetSnapshot()` 上报 `Status="paused"`、速率为 0，且**不推进 `LastTotal`**，因此累计值冻结、恢复后增量从冻结点继续（不会出现恢复瞬间的巨大尖峰）。

## 5. 关键实现说明与踩过的坑

**必须用 payload PID。** 事件头 PID 在内核网络事件里往往是接收中断所在的任意进程，不是流量归属方。TraceEvent 的 `KernelTraceEventParser` 已在内部把 payload PID 写回 `data.ProcessID`，所以直接读它即可。

**Event ID 18（`TcpIpTCPCopy`）不能累加。** 它和 `Data received` 是同一批数据的两次观察，订阅了下载量会翻倍。代码里刻意没有挂这个回调，改动时不要"顺手补全"。

**TraceEvent 3.2.6 的类名拼写错误。** IPv6 UDP 事件的数据类叫 `UpdIpV6TraceData`（`Udp` 拼成了 `Upd`），不是笔误，照抄即可。

**`PipeDirection.Out` 的管道无法反向使用**，所以暂停命令走的是独立的第二条控制管道，而不是复用快照管道。

**Rust 侧不要引 `windows-sys` 去调 `CreateFileW`。** 试过，`CreateFileW` 被 `Win32_Security` feature 门控、`ReadFile` 在 `Win32_System_IO`、`GENERIC_READ` 在 `Win32::Foundation`，feature 组合很折腾。`std::fs::File::open` 在 Windows 上本身就是 `CreateFileW` + `OPEN_EXISTING`，对命名管道路径直接可用。

**`cargo build` 报 `failed to remove netpeek-app.exe: 拒绝访问 (os error 5)`** 是上一次运行的实例还占着文件：`taskkill //F //IM netpeek-app.exe`。

**UI 不要以管理员运行。** Windows UIPI 会阻止 UI Automation 访问提权进程，界面就没法用自动化工具验证了。用 `explorer.exe <exe路径>` 可以从提权终端启出普通权限进程。采集服务反过来必须提权。

## 7. 阶段 1 补验（2026-09-04，`scripts/verify-etw-scenarios.ps1`）

新增自动化验证脚本，覆盖技术选型第 12 节中可在本机自动跑的场景，**8 项全部通过**：

- **S1 连续 10 次 curl 短连接**（每次独立 TCP 连接，共 50MB）：累加 4 帧下载字节 ≈ 50.5MB，`EventsLost=0` → 短连接归因完整、不丢事件。
- **S2 进程快速退出**：短命 curl 下载 5MB 后立即退出，退出后条目仍保留（30 帧剪枝前），字节完整归因（5MB/5MB）。
- **S3 UDP 报文**（QUIC 同类 UDP 通道）：UdpClient 发 50×1KB 报文，按 sender PID 断言累计上传 50KB/50KB → UDP 归因完整。
- **S4 与第二个 ETW 会话并存**：logman 再开一个 Kernel-Network 实时会话（GUID `{7DD42A49-5329-4832-8DFD-43D979094A9B}`，0x10），并存期间下载 5.4MB 归因完整、`EventsLost=0`、会话可正常删除。

**关键发现（产品行为）**：存活时间短于快照周期（1s）的短命进程，**字节归因完整，但进程名解析失败（Name=""）**——快照线程每秒查一次 `ProcessMetadataCache`，进程已退出时拿不到名字。UI 已有兜底：空名进程在表格中显示「(系统/未归因)」（main.js:524、563），归因覆盖率只统计有名进程。数据不丢，属预期行为，不需要改采集逻辑。

**脚本要点**（踩坑记录）：
- 断言语义：短连接/并存场景**按 `TotalDownloadBytes` 逐帧累加**断言，不能用「DownloadTotal 总和增量」——后者会被 30 帧剪枝的旧进程条目抵消（套件跑久后旧 curl 条目被剪掉，总和反而下降）。
- 快速退出的短命进程断言**按新 PID 条目**（不在 base 帧 PID 集合中）查找，不能按 `Name -like 'curl*'`（Name 为空）。
- PowerShell 的 `BinaryReader.Dispose()` 会关闭底层管道流：`Read-Snapshot` 每次新建 reader 必须传 `leaveOpen: $true`，否则读一帧后管道被关，后续帧报 "Cannot access a closed pipe"。
- `logman create trace` 会话名带时间戳（`netpeek-coexist-HHmmss`），避免上一次失败运行残留的同名会话导致 create 失败。
- 函数名不能用 `Rd`（PowerShell 内置别名 `rd`=Remove-Item，会覆盖函数定义）。

验证脚本用法：`pwsh -ExecutionPolicy Bypass -File scripts\verify-etw-scenarios.ps1`（需采集服务已管理员运行；本地 HTTP 服务脚本自动起/复用 18081 端口）。

## 8. 阶段 5 打包（2026-09-04）

### 8.1 机制

- **采集服务 self-contained 单文件**：`scripts/build-installer.ps1` 先 `dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true` 产出 71MB 单文件 exe（LocalSystem 服务不依赖用户装 .NET 运行时）。
- **WiX fragment 合并**（`src/NetPeek.App/src-tauri/installer/collector.wxs`）：Tauri 生成的主 wxs 里 `DirectoryRef Id="INSTALLDIR"` 下加 `collector` 子目录，`Component` 装 `NetPeek.Collector.exe` 并挂 `ServiceInstall`（`Account="LocalSystem" Start="auto" Type="ownProcess"`）+ `ServiceControl`（`Stop="both" Remove="uninstall" Wait="yes"`）。`tauri.conf.json` 的 `bundle.windows.wix.fragmentPaths` + `componentGroupRefs` 把 fragment 并进 MSI。
- **Tauri 内置**：WebView2 检测（RegistrySearch `{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` + downloadBootstrapper CustomAction）、MajorUpgrade 升级清理（UpgradeCode 稳定即可）、perMachine 安装范围。

### 8.2 实测结果

- **构建**：`pwsh -File scripts/build-installer.ps1` 产出 `NetPeek_0.1.0_x64_en-US.msi`（33.9MB）。
- **安装**：`msiexec /i` 后服务 `NetPeek.Collector` 为 Running/Automatic（LocalSystem），文件落 `C:\Program Files\NetPeek\`（netpeek-app.exe + collector\NetPeek.Collector.exe），管道快照 `status=ok EventsLost=0`。
- **升级**：版本号临时升 0.1.1 重装验证 MajorUpgrade——产品记录干净替换为单条 0.1.1、旧 0.1.0 移除、服务保持 Running/Automatic、快照正常。
- **卸载**：`msiexec /x` 后服务移除、`C:\Program Files\NetPeek\` 清空。

### 8.3 踩坑

- **Git Bash 会把 msiexec 的 `/i` `/x` `/qn` 参数改写**：MSYS 路径转换把 `/i` 变 `I:/`、`/qn` 变 `C:/Program Files/Git/qn`，msiexec 收到乱参数后挂起（CPU 0、永不退出）。**必须用 PowerShell 的 `Start-Process -ArgumentList @("/i","...msi","/qn",...)` 数组传参**，或 `MSYS_NO_PATHCONV=1` 前缀，不要直接从 Git Bash 调 msiexec。
- **WiX 相对 Source 路径解析点是 light 的 cwd**（`target/release/wix/x64`），而 Tauri bundler 每次先 `remove_dir_all` 清空该目录——所以 collector.wxs 的 `File Source` 不能用 `collector\NetPeek.Collector.exe`（会被清掉报 LGHT0103），改用 `..\..\NetPeek.Collector.exe` 指到 `target/release/`（不被清空），构建脚本把 exe 复制到那里。
- **fragment 里不要用 `$(var.Win64)`**：该变量只在 main.wxs 定义，fragment 单独 candle 时报 CNDL0150；硬编码 `Win64="yes"` 即可。
- **DisplayName/Description 用 ASCII**：中文会触发 LGHT0311（code page 1252）编码错误。
- **卸载日志尾部出现 `MainEngineThread is returning 1605`**（ERROR_UNKNOWN_PRODUCT）通常是同一条复合命令重复调了两次 `/x`（第二次产品已不存在）；以可观察状态（服务没了、文件没了）为准确认卸载成功。

### 8.4 待发布前处理（本机无法自动化）

- **代码签名**：需要证书，当前无，发布前用 Authenticode 签名 netpeek-app.exe 与 NetPeek.Collector.exe（及 MSI）。
- **人工验收**：休眠恢复、Windows 10 22H2 覆盖、浏览器真实大文件下载归因——需有对应环境或人工操作，无法在本机自动跑。

### 9.4 验收方法与查出来的实际缺陷

用一个临时的 `window.__TAURI__` 假桥接在普通浏览器里渲染四屏，headless Chrome + CDP 把视口锁死
1180×720 截图，交给 judge 子代理逐屏看。**脚手架（`ui/_preview*.js|html`、`.preview-shots/`）验收完已删除**
——`tauri.conf.json` 的 `frontendDist` 指向整个 `ui/` 目录，留在那里会被打进安装包。
未被引用的 `ui/vendor/uPlot.*` 也一并删了（图表是自己用 canvas 画的，charts.js 开头写了为什么不用 uPlot）。

这一轮真正查出来的代码缺陷：

- **实时折线图长期画成虚线**。`dashFrom` 约定「从这个下标起转虚线（暂停态）」，未暂停时 main.js 传 `-1`，
  charts.js 只判了 `typeof === 'number'`，于是实线段 `to <= from` 直接返回、虚线段从 -1 画到末尾——
  整条曲线都是虚线，等于界面一直在说「已暂停」。
- **顶栏「今日合计」的单位被裁掉**。顶栏是 `auto 1fr auto` 三列，实时屏多了视图胶囊和搜索框，
  左组放不下就把尾巴裁在岛外，只剩一个没有单位的数。改成左组 `flex:none`、第三列 `minmax(0,auto)`、
  搜索框 `flex: 0 1 240px; min-width: 132px`——窗口挤的时候先让搜索变窄。
- **`[hidden]` 被组件样式盖掉**。界面里绝大多数容器自带 `display:flex/grid`，会覆盖 UA 的 `[hidden]{display:none}`，
  结果外观屏底下叠着历史屏。加一条全局 `[hidden] { display: none !important; }` 放在所有组件规则之前。
- **数据岛的隐式 auto 行被 10 行表格顶到 392px**，把图和表一起挤出 250px 高的岛外；
  `.data-live` 必须显式写 `grid-template-rows: minmax(0, 1fr)`。
- **y 轴标注被裁成「00 MB/s」**。52px 的 y 轴槽在 11px 等宽下只放得下约 6 个字符，
  界面里的「10.00 MB/s」右对齐后从左边被切掉前几位。charts.js 另开一套坐标专用的紧凑格式（`axisBytes` / `axisRate`）。
- **归因覆盖率用了琥珀色**。琥珀是下载的专属语义（§1.2），改回正文色；
  它的点点下划线在 12px 下会和「已归因」糊成一条实线，加了 `text-underline-offset: 3px`。
- **排行行被 flex 压扁**。列向 flex 里的行默认可压缩，8 行 32px 塞进 130px 的槽会一起被压成 18px，
  图标连带被挤扁、列表永远不滚动；`.rank-row` 要 `flex: none`。没有真实图标时退回首字母牌，
  空的灰方块会在行首读成一条竖色条（§3.7 禁止项）。
- **滚动条用系统经典样式**，在暗色岛屿里画出亮灰滑块和上下箭头按钮。改成 `::-webkit-scrollbar` 自绘；
  注意标准的 `scrollbar-width` 一旦设了，Chromium 就会忽略所有 `::-webkit-` 规则，两者不能混用。
- **设置屏「采集服务」列只有说明、没有可操作项**，下三分之一空着。补了暂停/恢复采集
  （复用 `send_control_command`，走控制管道），措辞与顶栏状态胶囊统一成「监控中 / 已暂停 / 异常」——
  之前这一列写「运行中」，同一个信号在两个岛上叫两个名字。

judge 报的问题里有两类不是缺陷，是它自己读错了像素，已用取样驳回：顶栏上传数字被指成琥珀色
（实测 RGB(111,151,181)，与图例和表格上传列的 RGB(111,144,171) 一致，下载是 RGB(219,130,56)）；
「登录时自动启动」折行后缩进丢失（实测第二行左沿 x=53，正是标签文字列，第一行行带里的 x=31 是复选框本身）。
