## 2. 已完成并验证的功能

### 采集端（`src/NetPeek.Collector`）

- **ETW 会话**（`Sources/EtwSnapshotSource.cs`）：会话名 `NetPeek.Collector`，订阅 `KernelTraceEventParser.Keywords.NetworkTCPIP`，覆盖 TCP/UDP 的 IPv4+IPv6 收发与重传。启动时清理残留同名会话。
- **归因规则**：统一读 payload PID（TraceEvent 已在 `FixupData` 把 payload PID 写回 `data.ProcessID`）；**刻意不订阅 Event ID 18**（`TcpIpTCPCopy`），否则下载量翻倍；重传单独累计，不混入上传量。
- **PID 复用处理**：进程身份键 = PID + 进程启动时间，检测到复用则清零重计。进程退出且连续 30 帧无流量后从字典移除。
- **命名管道服务端**（`Ipc/SnapshotPipeServer.cs`）：`\\.\pipe\NetPeekCollector`，`PipeDirection.Out` 单向，帧格式 = 4 字节小端长度 + UTF-8 JSON，1000ms 一帧。客户端断开后自动回到监听。
- **反向控制通道**（`Ipc/SnapshotControlServer.cs`，新增）：`\\.\pipe\NetPeekCollectorControl`，`PipeDirection.In`。命令为单行 UTF-8 文本 `pause` / `resume` / `toggle`（不区分大小写）。UI 每发一条命令建一次短连接，写完即断。
- **暂停语义**：`ISnapshotSource` 增加 `Pause()` / `Resume()` / `IsPaused`。暂停时 ETW 回调内 `Add`/`AddRetransmit` 直接短路（不再累计），`GetSnapshot()` 上报 `Status="paused"`、速率为 0，且**不推进 `LastTotal`**，因此累计值冻结、恢复后增量从冻结点继续（不会出现恢复瞬间的巨大尖峰）。

### UI（`src/NetPeek.App`）

- **管道客户端**（`src-tauri/src/pipe.rs`）：用 `std::fs::File::open` 直接打开管道路径（Windows 上等价于 `CreateFileW` + `OPEN_EXISTING`），无需 `windows-sys`。按帧读取后 `emit` Tauri 事件 `snapshot`；连接状态走 `pipe-status`。断线 1s 后自动重连。`send_control()` 用 `OpenOptions::new().write(true)` 打开控制管道写一行命令。
- **托盘**（`src-tauri/src/lib.rs`）：菜单「打开主界面 / 暂停监控 / 退出」，左键点击唤出主窗；关闭主窗改为隐藏到托盘。暂停菜单项文案在「暂停监控 ⇄ 继续监控」间切换，命令走 `pause`/`resume`。
- **进程表虚拟化**（`ui/main.js`）：上下 spacer `<tr>` 撑滚动高度，只渲染可视区 ± 8 行；滚动用 `requestAnimationFrame` 节流。实测 DOM 节点从 316 降到 127。
- **实时速率折线图**：uPlot 1.6.32（MIT）以 IIFE 形式 vendored 在 `ui/vendor/`，无打包器。时间窗 10s / 1m / 5m 切换，样本只保留最近 5 分钟。
- **视图切换**：「按进程 / 按应用」。按应用时以进程名（小写）为键聚合所有指标，PID 列头变为「进程数」，单元格显示 `×N`。
- **状态提示**：`ok` → 监控中；`paused` → 已暂停；其他 → 采集服务异常（需管理员权限）；`EventsLost > 0` → 监控中 · 丢事件 N。
- **深浅色主题跟随系统**：CSS 变量 + `@media (prefers-color-scheme: light)` 两套色板，`color-scheme: light dark` 让滚动条与原生控件同步。uPlot 配色从 CSS 变量读取，监听 `matchMedia` 变化时销毁重建图表以换色。
- **Top 4 应用卡片 + 底部状态栏**（2026-09-03 新增）：卡片按应用聚合取累计流量前 4，显示图标/名称/实时速率/占总流量百分比条；底部状态栏显示服务状态（含丢事件）、会话时长（来自 `SessionStartedUnixMs`）、归因覆盖率（能解析出进程名的字节占比）。

## 4. 构建 / 运行 / 验证

```bash
# 采集服务（需管理员，否则 ETW 会话开不起来，快照 Status=error）
dotnet build src/NetPeek.Collector/NetPeek.Collector.csproj
# 以管理员启动：
pwsh -NoProfile -Command "Start-Process 'src\NetPeek.Collector\bin\Debug\net8.0-windows\NetPeek.Collector.exe' -Verb RunAs -WindowStyle Hidden"

# UI（普通权限，不要提权，否则无法用 UI 自动化工具观察）
cd src/NetPeek.App/src-tauri && cargo build
explorer.exe "target\debug\netpeek-app.exe"

# 自动化验证
pwsh -ExecutionPolicy Bypass -File scripts/verify-collection.ps1   # 打印 10 帧真机快照
pwsh -ExecutionPolicy Bypass -File scripts/verify-pause.ps1        # 暂停/恢复链路断言
```

两个脚本都会自提权。`verify-pause.ps1` 的完整输出同时写到 `%TEMP%\netpeek-verify-pause.log`（提权后新窗口会关闭，从日志读结果）。

## 5. 关键实现说明与踩过的坑

**必须用 payload PID。** 事件头 PID 在内核网络事件里往往是接收中断所在的任意进程，不是流量归属方。TraceEvent 的 `KernelTraceEventParser` 已在内部把 payload PID 写回 `data.ProcessID`，所以直接读它即可。

**Event ID 18（`TcpIpTCPCopy`）不能累加。** 它和 `Data received` 是同一批数据的两次观察，订阅了下载量会翻倍。代码里刻意没有挂这个回调，改动时不要"顺手补全"。

**TraceEvent 3.2.6 的类名拼写错误。** IPv6 UDP 事件的数据类叫 `UpdIpV6TraceData`（`Udp` 拼成了 `Upd`），不是笔误，照抄即可。

**`PipeDirection.Out` 的管道无法反向使用**，所以暂停命令走的是独立的第二条控制管道，而不是复用快照管道。

**Rust 侧不要引 `windows-sys` 去调 `CreateFileW`。** 试过，`CreateFileW` 被 `Win32_Security` feature 门控、`ReadFile` 在 `Win32_System_IO`、`GENERIC_READ` 在 `Win32::Foundation`，feature 组合很折腾。`std::fs::File::open` 在 Windows 上本身就是 `CreateFileW` + `OPEN_EXISTING`，对命名管道路径直接可用。

**`cargo build` 报 `failed to remove netpeek-app.exe: 拒绝访问 (os error 5)`** 是上一次运行的实例还占着文件：`taskkill //F //IM netpeek-app.exe`。

**UI 不要以管理员运行。** Windows UIPI 会阻止 UI Automation 访问提权进程，界面就没法用自动化工具验证了。用 `explorer.exe <exe路径>` 可以从提权终端启出普通权限进程。采集服务反过来必须提权。

**PowerShell 脚本用 `pwsh` 跑。** 脚本是 UTF-8 无 BOM，Windows PowerShell 5.1 会按 GBK 读导致中文乱码并解析失败；PowerShell 7 默认 UTF-8。

**uPlot 图例在悬浮前值为 `null`**，需要给 series 配 `value: (u, v) => v == null ? '--' : fmtRate(v)`，否则显示 "null B/s"。

**Tauri 前端要访问 `window.__TAURI__`** 必须在 `tauri.conf.json` 里设 `app.withGlobalTauri: true`（无打包器方案下没有 import 通道）。
