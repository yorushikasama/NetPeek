① 当前设计评估：五个根本问题

结论先行：现版不是「细节不好看」，而是空间分配、信息密度、视觉语言三个层面的方向性问题。逐条如下，右侧是新设计给出的答案。

问题具体表现（证据）新设计的对策
空间倒挂 最致命 实时屏约 40% 的面积给了「留白区」——一块只为背景图呼吸、不放任何数据的区域；核心带宽图被压在底部 250px，进程表只剩 ~5 行可见。监控工具看不到监控数据。 删除留白区。带宽图升为主区上半主角，进程表占满剩余高度（~12 行可见）。背景图改为全屏底层，面板微透即可保留「浮在底图上」的特色，不再为它牺牲面积。
信息密度过低 380px 宽检查栏的默认总览态只有 2 个数字 + 一个 NP 占位块；外观、设置两个屏内容贫瘠（各 3~5 个控件）却要占整屏；顶栏一行塞 7 类元素。 检查栏收窄至 300px 并填满有效内容（今日卡 + 30 天图 + Top 进程/选中详情）；外观并入设置；顶栏只留状态、元信息、速率、窗口钮，搜索下放到进程表头（就近原则）。
视觉语言分裂 主窗是暖色消费级「漂浮岛屿」（琥珀+米中性+毛玻璃），迷你窗是科幻「能量球」，图表是橙蓝工业语义——三套气质。毛玻璃在无背景图时纯耗 GPU。 统一为「深色技术底」：蓝黑底 + 1px 低对比边线分层（弃用投影和毛玻璃），琥珀/蓝只留给数据语义，交互用中性色。迷你窗同源换肤。
信息架构过繁 主题三模式（标准取色 / AI 自适应 / 定制）对普通用户过于复杂；外观与设置分两屏，导航 4 项；设置屏三列卡片配平仍显拼凑。 外观并入设置，导航 4→3。设置改为「左分区导航 + 右表单」（Windows 设置心智），主题三模式收敛为外观区内的三张卡片，AI 降为高级选项。
历史屏被压缩 历史数据挤在 250px 高的数据岛内：工具栏、柱图、排行互相争抢，柱图高度不足，趋势难以辨认。 历史屏主区全高：工具栏一行、柱图占满主区（~400px）、底部日详情行；排行移入右栏与实时屏同构。

新设计五条原则

1. 数据密度优先
每一寸面积都要回答一个用户问题。
2. 一屏一焦点
实时 = 带宽图 + 进程表；历史 = 趋势 + 排行。
3. 一种语言
深色技术底 + 双语义色 + 中性交互，主窗与迷你窗同源。
4. 装饰让位功能
无留白区、无毛玻璃、无投影层级；分层靠底色差 + 1px 边线。
5. 架构瘦身
外观并入设置，导航 4→3；控件就近放在它作用的对象旁。

② 设计语言

蓝黑技术底（非暖黑），琥珀与蓝只承担「下载/上传」数据语义，交互一律中性色——语义不再被装饰稀释。分层用底色差 + 1px 边线，不用投影。

迁移影响面（实施时的注意点）

1. 纯前端重构：Rust/采集端零改动；所有 invoke 接口、事件名、数据格式保持。
2. token 整体换表：styles.css 的 :root 变量一换，80% 视觉自动迁移；岛屿毛玻璃、投影、stage 相关规则整段删除。
3. 结构改动集中：index.html 的 shell 从「四块漂浮岛」改为「顶栏 + rail + 主区（中心+右栏）」；外观屏删除，其功能搬入设置屏分区。
4. 需要重新验证的既有能力：主题取色（背景图 → 主色）在「面板不透明度」模式下重新标定默认值；三档响应式断点按新栅格重算；canvas 图表颜色改读新 token。
5. 功能零删减：暂停/恢复、排序、搜索、检查详情、历史导出、主题自定义、迷你窗两形态全部保留；变化只在「放哪里、长什么样」。
