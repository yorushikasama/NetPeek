NetPeek 界面重设计稿 v2 · 朴素基底，皮肤承载个性

2026-09-12 ・ 范围：实时 / 历史 / 设置（合并外观）/ 迷你窗 + 设计语言与皮肤系统
v2 修订（按反馈）：应用本体不要鲜明特色，朴素就行，个性靠皮肤弥补。据此：① 基底去性格化——v1 的蓝黑底改中性灰黑，chrome（导航选中、表格选中、主按钮、开关、品牌标）全部改中性色，琥珀/蓝只留给下载/上传数据语义；② 皮肤升级为唯一个性层——所有视觉决策走 token，皮肤 = 一套 token 覆写，原「标准取色 / AI / 定制」三模式统一收编为皮肤；③ 布局骨架不变（删留白区、密度优先、外观并入设置等 v1 结论全部保留）。
① 评估② 设计语言与皮肤③ 实时屏 ④ 历史屏⑤ 设置屏⑥ 迷你窗⑦ 栅格与迁移

① 当前设计评估：五个根本问题

结论先行：现版不是「细节不好看」，而是空间分配、信息密度、视觉语言三个层面的方向性问题；且「暖琥珀岛屿」把性格烙进了基底——换肤也换不掉它。逐条如下，右侧是新设计的对策。

问题具体表现（证据）新设计的对策
空间倒挂 最致命 实时屏约 40% 面积给了「留白区」——只为背景图呼吸、不放任何数据；核心带宽图被压在底部 250px，进程表只剩 ~5 行可见。 删除留白区。带宽图升为主区主角，进程表占满剩余高度（~12 行可见）。背景图改为全屏底层，面板微透即可，不再为它牺牲面积。
信息密度过低 380px 检查栏默认总览态只有 2 个数字 + NP 占位块；外观、设置两屏内容贫瘠却各占整屏；顶栏一行塞 7 类元素。 检查栏收窄至 300px 并填满有效内容；外观并入设置；顶栏只留 4 类元素，搜索下放到进程表头（就近原则）。
性格烙进基底 v2 新增 暖琥珀 + 米中性 + 毛玻璃写死在基底里，选中态、主按钮、光晕全是琥珀——这不是「皮肤」，是「胎记」；迷你窗的能量球又是另一套科幻气质。 基底中性化：chrome 全部中性色，彩色只属于数据语义；个性全部由皮肤层（token 覆写）承载——默认皮肤就是「朴素」，想要风格换皮肤。
信息架构过繁 主题三模式（标准取色 / AI 自适应 / 定制）概念复杂；外观与设置分两屏，导航 4 项。 外观并入设置，导航 4→3；三模式收编为「皮肤」：默认朴素 / 浅色 / 跟随背景图（含 AI 取色·高级）/ 自定义。
历史屏被压缩 历史数据挤在 250px 高的数据岛内，柱图高度不足，趋势难辨认。 历史屏主区全高：柱图 ~400px，排行移入右栏与实时屏同构。

新设计六条原则

1. 数据密度优先
每一寸面积都要回答一个用户问题。
2. 一屏一焦点
实时 = 带宽图 + 进程表；历史 = 趋势 + 排行。
3. 朴素基底 v2
chrome 全中性色，不预设性格；工具就该安静。
4. 皮肤承载个性 v2
一切视觉决策走 token；风格 = 换一套 token，结构永不变。
5. 装饰让位功能
无留白区、无毛玻璃、无投影；分层靠底色差 + 1px 边线。
6. 架构瘦身
外观并入设置，导航 4→3；控件就近放在它作用的对象旁。

② 设计语言与皮肤系统

基底是中性灰黑（无蓝调无暖调），交互强调用「中性反白」；琥珀/蓝只出现在数据上。皮肤 = 一套 token 覆写，可以改变底色、面板、边线、语义双色、强调色、圆角——结构与布局永不变。

皮肤 = token 覆写（结构不变，示例四款）

皮肤可覆写的维度：--bg / --panel / --panel-hi / --panel-2 / --line×2 / --text×3 / --down / --up / --accent / --accent-ink / --sel-bar / 状态三色 / 圆角三档。 皮肤不能改：栅格、字号阶、间距节奏、组件结构——所以任何皮肤下可用性一致，换肤是安全的。
与原主题系统的关系：原「标准取色」= 跟随背景图皮肤；原「AI 自适应」= 该皮肤的高级取色器；原「定制」= 自定义皮肤（token 编辑器）。概念从三套并轨为一套。

皮肤架构（实施层）

· 皮肤文件 = JSON token 表：{ "bg": "#1b1d21", "panel": "#22252a", "down": "#f0963f", "accent": "#e3e5e9", ... }，运行时注入 :root，即换即生效。
· 内置四款：默认朴素 / 浅色 / 琥珀暖意 / 跟随背景图（取色器：本地色阶分析，AI 为高级选项）。
· 自定义皮肤：编辑器 = token 表单（颜色选择器 + 圆角滑块），基于任一皮肤另存；这就是原「定制模式」的归处。
· 约束：canvas 图表颜色全部读 token（现有 cssVar 机制已具备）；皮肤不许含布局数值——JSON schema 里就没有布局字段。

迁移影响面

1. 纯前端重构：Rust/采集端零改动；invoke 接口、事件名、数据格式全保持。
2. token 整体换表：styles.css :root 换成朴素基底；毛玻璃、投影、stage、琥珀 chrome 相关规则整段删除。
3. 结构改动集中：index.html 从「四块漂浮岛」改为「顶栏 + rail + 主区（中心+右栏）」；外观屏删除，功能搬入设置屏皮肤分区。
4. 需重验的既有能力：背景图取色在皮肤架构下重接（跟随背景图皮肤）；三档响应式断点按新栅格重算；canvas 图表读新 token。
5. 功能零删减：暂停/恢复、排序、搜索、检查详情、历史导出、迷你窗两形态全部保留；变化只在「放哪里、长什么样、谁来定性格」。
