## 自适应透镜（auto-levels）：近黑壁纸「透不出形」的修复（18:20，用户截图反馈「不透明度拉到 0.93 底图还是无法透出来，质感不够高级」）

**两个根因**：
1. **滑杆被可读性地板拿走**（上一轮遗留的机制缺陷）：`theme-ui.syncBackdropGuard` 曾把 `els.opacity.min` 抬到 `guard.floor`，并把 `value` 与 `state.panelOpacity` 一起吸附过去。近黑壁纸下 floor 顶到 0.93 → 滑杆拉到底就是 0.93，底图等于看不见。修法：`els.opacity.min` 恒为 `MIN_PANEL_OP`（0.30），floor 只写 `--panel-op-floor`（漆层），**不动滑杆**。
2. **固定透镜把「低内对比」原样保留**：固定透镜把 `[0,1]` 整条映射进窄带（浅色 `contrast(.105) brightness(1.9)` → 输出 `[0.85,0.99]`，斜率 0.1995）。用户那张近黑星空的等效灰通道只落在 0.059–0.130（宽 0.071），×0.1995 只剩 0.014 → 面板不透明度 0.45 下**只剩 1.6/255**，看起来就是一块平色。压缩型的透镜天生救不了「自己没有对比」的图。

**修复（自适应透镜 = per-image auto-levels）**：
- `theme.js` 新增 `lensFromImage(lo, hi, tokens, scrim, brightness)`：按**这张图自己的**等效灰通道 p2–p98 反解 `contrast/brightness`，把这段灰**拉张开**铺满透镜输出带。闭式反解：`s = (t1−t0)/range`、`t = t0 − s·loV`、`b = 2t + s`、`c = s/b`（由 CSS filter 的 `out = in·(c·b) + 0.5·b·(1−c)` 逆推）。
- **带底 `t0 = 0.5·b·(1−c)` 就取固定透镜 in=0 处的输出**（浅色 0.85 / 深色 0.025）——「不违反明度带」那条线。选它的意义：自适应透镜的可读性**不低于**已经验证过的固定透镜，带内多出来的空间全部给底图的形。带顶 `t1 = min(固定透镜 in=1 的输出, 0.99)`。
- **必须先铺纱再反解**（第一版的坑）：透镜实际吃到的输入是「纱铺过的图」。用未铺纱的 `[lo,hi]` 反解、再把参数作用到铺纱后的输入 → 暗图会被整段推到带顶之上、全 clamp 成白，底图反而彻底消失（实测 `out(veiled(lo)) = 1.10 > 1`）。测试里留了这条反例断言钉住。
- 参数退化（`hi−lo < MIN_IMG_RANGE = 0.02` / 斜率上限 6 / `b ≤ 0`）→ 返回 `null`，回落固定 `LENS`，不给 JPEG 噪声送放大。
- `theme-ui.js`：`backdropLuminance` 重构为**一趟**块均值扫描、缓存进 WeakMap（`imageStats` 同时产出 `lum`（线性亮度分位，给守卫）与 `chan`（等效灰通道分位，给透镜）——两个口径必须同一批块）；新增 `imageRange` / `refreshLens`（按当前图 + 方向化纱浓度 + 背景亮度算透镜），经 `applyBackdrop({ lens })` 写 `--lens-filter`；`backdropFloor` / `backdropGuard` 增 `lens` 形参，**判定模型与实际渲染用同一组数**（否则判的和渲染的不是一回事）。
- 顺带修掉一个性能坑：`backdropLuminance` 原先每次调用（拖滑杆每帧）都重扫 + 重排整张 ImageData，现在有缓存。

## 玻璃透镜第三次返工：深色变全不透明的根因 + 契约自校准 + 归一化锚点（20:00，用户第二次报同一缺陷「不透明度拉到最低还是没有透出底图，现在深色也一样了，之前深色是可以的」）

**症状与实证**（不是猜的，是量出来的）：
- 深色皮肤实测 `op=1 floor=1`（滑杆被地板顶到全不透明）、`--lens-filter=saturate(1.5)`（透镜根本没接上）、带 `band(ch)=[0.05,0.05]`（退化成一个点）、底图的形 `p2p=0/255`（彻底看不见）。
- 浅色皮肤能透出来，但形只剩 `p2p=6-7/255`（旧写死透镜）——就是用户说的「粉白雾」。

**根因链（三环，缺一都不会坏）**：
1. **契约无解**：`GLASS_TIERS.dark` 声明次要字 `|Lc| ≥ 45`，而深色皮肤的次要字是一枚中灰（实测 token `#9b8f8b`）压在近黑底上 —— **|Lc| 的物理上限只有 ≈43**（连纯黑也只给 43.3）。契约恒假。
2. **无解时退化成一个点**：`lensBand` 当时写 `if (!meets(lo)) return [lo, lo]` → 斜率 0 → `lensParams` 返回 null → `lensOf` 为 null。
3. **null 的连带后果**：`backdropGuard` 退回「无透镜」分支，把 `--panel-op-floor` 顶到 1 → 面板全不透明 → **透镜失效不是「少了一层归一化」，而是「整个透明能力被拿走」**。
   结论：**任何把「透镜参数退化」当成无害兜底的写法都是错的**；宁可退化成恒等透镜（k=1/b=1），也绝不能返回 null。

**三处修复（`src/NetPeek.App/ui/theme.js`）**：
- **契约自校准**：新增 `GLASS_TIER_REL=0.75`，每档实际目标 = `min(声明档位, 该档在「对比最强端」实测对比 × 0.75)`。于是 `meets(tBest)` **恒真**，带在结构上不可能退化；兜底也从 `[X,X]` 改成整条带（恒等透镜，仍是**有效**透镜，不会变成 null）。浅色三档余量本来就大（白底 98/90/76 ×0.75 = 73/67/57 全高于声明），**浅色反解结果一格未动**；只有深色那枚贴天花板的次要字被松到 32.25。
- **归一化锚点从 `veiled(p2)` 改成 `veiled(0)`**（第三次返工的关键）：旧锚点把图的 `[p2,p98]` 映到带内、**截距为负**，于是**比 p2 更暗的像素会掉到带底之下**。而带是契约/守卫/像素审计三者的共同前提 —— 输出一旦越界，三条保证同时作废。实测踩到：用户壁纸里成片的近黑区（渲染在 `.top-meta` 那行后面）落到带外，像素审计量到弱字阶 `Lc 28.6`（旧窄带时代 60.3）。新锚点让 `out(0)=t0`、`out(veiled(1))≥t1`，**输出结构上不可能越过带底**；代价是图自己的范围只占带的一段 `factor=(hiV−loV)/(hiV−zeroV)`（近黑图≈100%、中调 55–75%），实测用户真图 factor≈0.90 几乎不损失。
- **删掉 `lensFromImage` 里的「截距 ≥ 0.05」钳位**：带底降到 0.613 之后，把暗图的最亮端送到带顶本来就需要大斜率（必然负截距），那条钳位会把最亮端按在带顶之下（实测 0.85 vs 0.99），等于把刚争来的带宽原样还回去。真正要防的发散只有 `b=2t+s ≤ 0`，交给 `b>0` 判据回落 `lensOf`。
- 顺带：`bandOf` 改为由 `lensBand` 派生；新增 `worstSurface()` / `glassTierTargets()`（导出，供回归脚本共用同一份口径）。

**手法留档**：
- 「底图的形」量尺 = 同一块面板拍两张（有底图 / 摘掉 `--theme-bg-image`），逐像素相减（面板自身内容在两张里是同一批像素、相减即抵消），再按 8×8 格取格均值求峰谷差 p2p。**不能用单图方差**（面板整体亮度会变，噪声盖信号）。实测基准：平色 ≈0–7，可见 ≥36。
