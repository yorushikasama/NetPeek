### ⚠️ 重要纠正：国旗 emoji 在 Windows 上根本不显示

**上一轮我判断错了**。上轮看到 headless 截图里国旗显示为「JP」，我判为
「headless 缺彩色 emoji 字体，真实 WebView2 会显示 🇯🇵」。**这是错的。**

事实：Windows 的 Segoe UI Emoji **故意不含国旗字形**（微软避免政治争议），
区域指示符对（U+1F1E6–U+1F1FF 组合）在 Windows 上恒渲染为两个字母。
浏览器、WebView2 一律如此。用 NotoColorEmoji polyfill 字体也不可靠——
内嵌 WebView 可能不支持 regional glyph 表或 CBDT/CBLC 彩色表，
社区明确说「PNG/SVG 图片才是唯一可靠方案」。

影响面：`ui/services.js` 的 `flagOf()` 生成的就是区域指示符，
对端列的国家标识对所有 Windows 用户都是失效的。

Sniffnet 的解法：`src/countries/flags_pictures.rs` 用 `include_bytes!`
把 200+ 个 SVG（flag-icons 命名规范）编译进二进制，尺寸常量
`ICONS_SIZE_SMALL=18` / `ICONS_SIZE_BIG=32`；`country_utils.rs` 做
Country→SVG 映射 + 属地归并（FR 覆盖 BL/GF/GP/MF/MQ/PM/RE/WF/YT，
AU|HM、NL|BQ、NO|BV|SJ、US|UM），`Country::ZZ` 走降级链：
loopback→COMPUTER、multicast→MULTICAST、broadcast→BROADCAST、
local→HOME、bogon→BOGON、否则 UNKNOWN。共 6 个语义图标（zz-*.svg）。

## 迷你窗「边框 / 3D 感」：审查 + 修复（真机取证）

用户反馈：悬浮面板**外面有一层边框**；悬浮球**周围有透明边框**、**没有 3D 感**。
搭了 CDP alpha 截图 + 逐像素分析 + Win32 窗口探针，查到 5 个**相互独立**的根因，
全部有实测证据，不是观感分歧。

### ⚠️ 关键知识 1：DWM 那圈边框来自 tao 的 undecorated_with_shadows

`tao-0.35.3/src/platform_impl/windows/window_state.rs:466`：
```rust
pub fn undecorated_with_shadows(&self) -> bool {
    self.contains(WindowFlags::MARKER_UNDECORATED_SHADOW)   // = Tauri 的 shadow（默认 true）
        && !self.contains(WindowFlags::MARKER_DECORATIONS)  // = decorations:false
}
```
`window.rs:1238` 创建时 `w += insets.left+right; h += insets.top+bottom`，
insets 由 `util::calculate_insets_for_dpi`() 算（= SM_CXSIZEFRAME + SM_CXPADDEDBORDER）。
**所以 `decorations:false` + 默认 shadow 的窗口，四周会被预留一圈 DWM 非客户区。**

实测迷你窗（`winprobe.py`，需先 `SetProcessDpiAwareness(2)`）：
- GetWindowRect **184×175**，DWM 扩展帧 **166×166** → 边框 左9 上0 右9 下9
- style `WS_CAPTION|WS_BORDER|WS_SYSMENU`（tao 的 `to_window_styles()` 无条件加，
  只有 `to_adjusted_window_styles()` 才在无 decorations 时移除，而那个只用于算客户区）
- `DWMWA_NCRENDERING_ENABLED = 1`

**修法（已实测有效）**：迷你窗加 `"shadow": false` → 重建后 DWM 帧边界 == 窗口矩形，
边框每边归 0。**主窗没加，所以主窗仍带这圈 9px（用户没抱怨，因为内容铺满不显）。**

### ⚠️ 关键知识 2：量窗口尺寸必须 DPI aware

本机屏幕 1920×1200 @144 DPI(150%)。非 DPI-aware 进程拿到的坐标被缩放：
窗口报 108、屏幕报 1280×800。**必须先 `shcore.SetProcessDpiAwareness(2)`**，
否则和 CDP 的 innerWidth 对不上，会推出错误结论。已加进 `desktop.py`。

### 五个根因

| # | 现象 | 根因 | 证据 |
|---|---|---|---|
| 1 | 面板外面一层边框 | DWM 非客户区（见上） | 窗口 184×175 vs DWM 帧 166×166 |
| 2 | 面板同样有边框感 | `.panel{inset:0}` 与窗口同尺寸 → `box-shadow 0 0 24px + 0 6px 20px` **全落在窗口外被裁**；反过来圆角 16px 外的四角**被自身的 box-shadow 填了色** | alpha 图 100% 非透明；左上角 alpha 12~23、左下 27~42（第二层向下偏 6px） |
| 3 | 球周围透明边框 | 光晕是圆、窗口是方 → 溢出被硬裁。halo `inset:-5px` + `::after` 的 `box-shadow 0 0 16px 3px` → 扩散半径 70 逻辑 px，窗口半宽仅 54 | alpha 扫描：r=70→80 全是 rgba(237,146,55) alpha 17→6；窗口四边中段 alpha 2~9，**四角为 0** → 读出"方框" |
| 4 | 首开球偏 | 首次显示窗口宽 **135** 而非 108（切一次形态才纠正） | CDP 视口：首开 135×108 → 面板 320×300 → 收回 108×108 |
| 5 | 球无 3D 感 | **确实没有球面光照**：`background:none`（纯色）、`boxShadow` 只有向外的光、`hasInsetShadow:false` | 现有 = 纯色圆 + 1px 描边 + 外发光 + 球心亮斑 + 旋转扇形；缺边缘暗化 / 镜面高光点 / 球面明暗 / 底部反光 |
